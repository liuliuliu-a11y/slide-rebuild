# PPT 复刻 Controller

负责当前页、输入模式、冻结任务书、问题分流和 checkpoint。执行边界以 ../SKILL.md 为准，质量标准以 ../acceptance.md 为准。

## 开始当前页

1. 固定一个 page_id、页序和 page_type；复用上游风格、来源和已确认决定。
2. generated-page 读取 ../references/generated-page-handoff.md，先核对父 manifest 的整套图片检查已通过、目录/任务书/图片版本一致，再承接当前页任务书、准确文字/数据、冻结图和已有回执。external-reference 安排源页读取与缺项核对，无需补做上游生图。
3. 锁定输出 PPTX、预览和工作资产目录；使用已存在的 output/work 或 projects 对应位置，禁止把产物散落桌面。
4. 明确原生文字/结构/表格/图表数据、独立图片层、背景保真和接受简化。
5. 封面核对标题/署名/日期/Logo，内容页核对结论、证据、数值单位与连接关系。
6. Planner 只补当前页缺少的重建计划，随后冻结 SKILL.md 中的 Frozen Page Brief。
7. 记录本轮新页/局部修改/共用工具变更范围及复用的构建能力、资产和证据。沿用原任务书与记录，不让角色重复填表或重建工具。

复用合格的上游生成资产及回执，不以“每个角色都要生成一次”为由增加调用。模型未返回时保留未确认状态；严格型号要求仍是实际条件。

## 推进与验收

- Builder 仅制作当前页，自查后交付真实预览和编辑证据。
- 按本 Skill 使用只读 reviewer 子代理（宿主允许时）；不可用则单独复核并说明 fallback，不将 builder 自评伪称独立签收。
- 将 reviewer 的 Blocking 与 Polish 分开，只把当前页必要问题发回同一 builder。
- 修复后重新导出，并复查变更区域；检查全部验收条件，不因外观漂亮跳过原生编辑。
- acceptance.md 第 7 节决定本轮新增检查；全部验收条件可由本轮验证与仍有效的既有证据共同支持，不把旧测试冒称新测。影响不明时扩大到相关页面。
- 共用工具实际变化时按 ../references/benchmark-evaluation.md 选受影响样例；普通小改不重跑整组基准。只改 Skill 不调用生图或制作测试页。
- 无阻塞时保存本页 PPTX、预览、资产/源码索引与 QA；有工具/来源缺口则单列，不能标为通过。
- generated-page 的 page_control 与授权范围从父任务继承。checkpoint 时展示当前页并等待继续；continuous_serial 时保存后复刻已冻结的下一页，不重复要许可。checkpoint 存档本身不增加批准要求。
- 冻结内容变化时反馈父流程使检查记录过期，待修正和必要复查后续做；不从复刻阶段自行启动下一页整页生图。
- 合并前仅选择已验收页；合并后重新检查顺序、原生对象、媒体/数据关系和真实渲染。

Controller 不在复刻阶段改写业务结论、增加页数、重做已确认风格或擅自简化主视觉。上游事实与参考图冲突时反馈到内容源，不能把模型文字作为新事实。
